# Application model settings

The application sidebar opens full-screen settings over the current library or game screen without remounting it. The navigation separates **API connections**, the global **Models** list and **Prompts**. Connection cards select an existing connection; **New connection** opens a searchable service catalogue alongside its setup form.

Service presets cover OpenAI, Anthropic, Google, Vertex AI, OpenRouter, Ollama Cloud, Cerebras, NanoGPT, DeepSeek, Vercel AI Gateway and custom endpoints. Presets supply the API format, base URL and key-management link; advanced settings expose the URL and format for editing. Entering a key and choosing **Select models** saves the connection, stores the key through the trusted host and reads the service's model catalogue where supported. A metadata-only connection can also be saved and models entered manually before supplying a key.

Vertex AI uses **Service Account JSON** by default. Paste a JSON key or import a file up to 64KiB; its project ID prefills an empty project field. The target project can be overridden independently of the key's owning project. Region defaults to `global`; regional endpoints such as `us-central1` are supported. The host-facing base URL is generated from these fields, including `/projects/{project}/locations/{region}/publishers/google`, and cannot be redirected to an arbitrary host. Project and region are part of credential binding; changing either requires explicitly saving the service account for that configuration.

The JSON is structurally validated in the UI and independently validated by each host, including its RSA private key. Only the fields required for authentication are retained; `token_uri` must equal Google's fixed `https://oauth2.googleapis.com/token`. **Verify service account authentication** uses a host-signed RS256 JWT grant with the Cloud Platform scope. Tokens are cached in host memory and renewed before expiry; neither JSON nor access tokens are returned to the UI after saving. Successful verification establishes OAuth authentication, not Vertex IAM permissions, enabled APIs, model availability or generation access. Vertex models currently use manual ID registration. Express API keys, ADC, workload identity and end-user OAuth are not implemented. Generation permissions are checked by actual requests through the separate AI execution integration.

Models reference a connection by its internal ID and retain a separate display name and provider-facing model ID. Catalogue selection prefills an editable model form. Multiple entries may use the same provider-facing ID with different names. The global list supports search, editing, deletion and default selection. Removing a connection requires confirmation and deletes its host credential and model entries. Removing the default model selects the first remaining model, or clears the selection when none remain.

Only explicit saves persist form edits. Closing an edited form, switching sections or selecting another item requires confirmation before discarding changes. Failed saves retain the draft; failed loads show a retry without replacing stored data. Metadata and host credential writes are separate: if the key write fails after metadata was saved, the message states that distinction and retains the key for retry. Writes prevent navigation or closure until completion. Switching connections aborts catalogue requests and ignores stale responses, including native requests that cannot be interrupted through the IPC bridge.

**Non-secret metadata only** is stored per device/browser profile under `helia:ai-settings` in `localStorage`. The parser validates references and rebuilds the known document fields before every save. Base URLs cannot include embedded credentials, query strings or fragments. Nothing here belongs to a game's content snapshot, authoritative state or history.

**Prompts** manages player-owned named presets with creation, duplication, deletion, active selection and JSON import/export. The editor exposes ordered prompt blocks, their types, special types and roles, text and formatting, chat ranges, cache depth, toggles and generation limits. Bodies are edited directly on each block, including `main`, `globalNote`, `persona` and `postEverything`; there is no separate Common Content section. Imports rebuild supported fields, excluding credentials and game-owned lorebook data. Legacy shared body fields are copied into their corresponding blocks when loading or importing; canonical configuration version 2 stores only block bodies. Previously unreferenced text is retained in disabled blocks. Only explicit saves persist edits; navigation and closure use the same unsaved-change guard as connection/model forms. Failed saves retain the draft. The last preset cannot be deleted.

Prompt blocks follow [RisuAI's editor](https://github.com/kwaroran/RisuAI/blob/main/src/lib/UI/PromptDataItem.svelte): collapsible cards with a name and delete/reorder controls in one header, followed by a single column of name, type, special type, prompt and role fields as applicable. Visible labels use RisuAI's Korean terminology; serialized field names and enum values stay out of the form labels.

**Import** immediately opens a file picker for `.json`, `.preset`, `.risupreset` and `.risup`. Selecting a valid file opens a new unsaved preset for review; **Save preset** persists it. Cancellation leaves the current draft intact, and replacing edited content uses the existing discard guard. Invalid files show an error without replacing the draft. Files and expanded binary containers are limited to 4MiB. The importer uses Risu's byte substitution, gzip/deflate, MessagePack and AES-GCM container format; the MessagePack decoder uses `msgpackr`'s no-eval entry point. Supported prompt fields still pass through the existing validators. JSON export remains available.

Prompt settings use the separate `helia:prompt-settings` document, with at most 64 presets and a 4 Mi-character document limit. The selected preset applies to all games. AI invocation captures a detached configuration once at its start; saving a new selection affects the next invocation, including existing sessions. Presets are never included in game definitions, game snapshots or session history. Game description, author's note and lorebook remain game content assembled through the selected preset's blocks. Missing settings start with a default preset; corrupt or unreadable settings report an error without resetting data.

Each applicable block has one role selector and one canonical `role`; chat and ChatML derive roles from their messages. Legacy Helia `role2` values are normalized into the former effective role when read and are omitted from subsequent saves and exports. Raw Risu JSON maps its block-specific `role`/`role2` into that same canonical field. Helia export envelopes use canonical parsing, preserving typed block roles on reimport rather than interpreting them as raw Risu fields.

API keys and service-account JSON go through [the credential protocol](./credential-protocol.ts) to the same-origin Node.js endpoint or the main-frame-only Tauri bridge. Neither host returns saved secrets to the UI. See [credential storage](../../storage/README.md#api-credential-storage-policy) for file locations and recovery. A credential is bound to its connection ID, API format and URL; changing the endpoint requires explicitly saving authentication for that address. Host requests require HTTPS except for HTTP loopback addresses. Redirects are refused, requests have a 15-second timeout, and paginated catalogues are bounded. Provider and OAuth error bodies are never displayed. Catalogue failures leave manual model entry available.

Model discovery uses the provider's list endpoint and does not send a generation request. A successful key save indicates persistence, not proof of generation permissions or model availability. Usage reporting, capability discovery and generation-parameter editing are not implemented in this settings screen. [AI generation and tool execution](../../games/ai/README.md) reuse these connections and model entries. Advanced API format selection also supports OpenAI Responses and Google Interactions.

Tests cover configuration validation, encrypted persistence and recovery, endpoint binding, native command authorization, provider catalogue parsing and pagination, stale responses, persistence failures, connection/model management, destructive-change confirmation, modal keyboard behavior, small viewports and preservation of the existing game screen. UI tests mock the credential host; they never require live service keys.
